# GOOSE-OCC v1.4.0 Data Pipeline

This document records the frozen dataset contract used by VisibilityOcc. The
authoritative generation code is
`/path/to/SurroundOcc/tools/generate_occupancy_goose`; the
released files under `/path/to/GOOSE-OCC` are inputs, not
outputs to be regenerated by the training project.

## Construction stages

1. Audit the official semantic archive and GOOSE-DB bags with
   `audit_goose_db.py`, `index_goose_bags.py`, `match_goose_targets.py`, and
   `extract_goose_poses.py`.
2. Curate target frames, fuse temporally aligned semantic LiDAR points, map
   the seven occupied classes, voxelize to
   `pc_range=[0,-16,-4,50,16,4]`, `voxel_size=0.25`, and write sparse OCC
   labels with `generate_goose_occ.py`. Validate with `validate_goose_occ.py`.
3. Create target infos and route-level train/validation splits with
   `create_goose_infos.py` and `design_goose_split.py`. The release contains
   2,877 train and 490 validation targets, using only
   `CAM_WINDSHIELD_VIS`.
4. Extract at most ten causal camera histories with
   `extract_goose_temporal.py`, validate pose/timestamp joins, and finalize
   `temporal_infos_{train,val}.pkl`. Histories are real frames only; no target
   duplication is allowed.
5. Generate SAM3 propagated history semantics and confidence maps with
   `generate_goose_temporal_pseudo_labels.py`, finalize and audit them with
   `finalize_goose_temporal_pseudo_labels.py` and
   `audit_goose_temporal_pseudo_labels.py`.
6. Generate Metric3D v2 pseudo-depth for target and history images with
   `generate_goose_metric3d_depth.py`, then finalize and validate the uint16
   PNG `/256` encoding. These maps are weak supervision, not depth GT.
7. Generate and validate LiDAR/pose-derived observation-state masks with
   `generate_goose_observation_masks.py`, `finalize_goose_observation.py`, and
   `validate_goose_observation_masks.py`. The released protocol defines the
   visible and occluded valid domains used only by evaluation.
8. Build checksums/release metadata with `build_goose_release.py` after all
   relative paths have been finalized.

The released dataset README and metadata are authoritative for v1.4.0. The
generator-side `README.md` still identifies some temporal products as v1.3.0;
those passages describe the preceding construction stage, not the version of
the frozen release consumed here.

The base PKLs contain `metadata.version=goose-occ-v2.0`. That value is a
legacy infos-schema/API token hard-coded by `create_goose_infos.py`, not the
dataset release identifier. `VERSION` and `release.json` remain authoritative
and both identify the frozen release as `1.4.0`.

The frozen release `CITATION.md` also retains a v1.3.0 example string. Cite the
original GOOSE paper as required, but report `GOOSE-OCC v1.4.0` in this work,
consistent with `VERSION` and `release.json`. VisibilityOcc does not edit the
frozen release to repair this documentation mismatch.

## Auditable construction contract

The target-selection funnel starts from 8,814 official semantic frames. Of
8,673 frames with complete RGB, 2D labels, semantic cloud, and 3D labels,
5,364 belong to readable downloaded archives. Exact raw-LiDAR timestamp joins
retain 3,293 targets and the validated nearest-timestamp policy retains 74
more. The final 3,367 targets all have calibration and a global LiDAR pose.
The split is by complete route, not by frame: 2,877 targets are assigned to
train and 490 to validation, with no sequence shared across splits.

| stage | principal input | released or intermediate output | validator |
| --- | --- | --- | --- |
| source audit | official semantic ZIPs and GOOSE-DB archives | semantic/archive inventories | `audit_goose_db.py` |
| timestamp join | semantic filenames and raw VLS-128 messages | target/source matches | `match_goose_targets.py` |
| pose extraction | bag TF, TF-static, and camera calibration | target/source poses and calibration | `extract_goose_poses.py` |
| target curation | matched frames with complete modalities | `manifest.csv` and copied target payload | `curate_goose_occ.py` |
| OCC construction | semantic clouds, fusion provenance, poses | sparse `(N,4)` OCC arrays | `validate_goose_occ.py` |
| split and base infos | manifest, poses, calibration | route split and `goose_infos_*.pkl` | release/infos checks |
| temporal extraction | raw camera messages and pose timeline | causal histories and `temporal_infos_*.pkl` | `validate_goose_temporal.py` |
| history semantics | future official target prompts and causal RGB | SAM3 labels and confidence | `audit_goose_temporal_pseudo_labels.py` |
| pseudo depth | every released target/history RGB | Metric3D uint16 depth PNGs | `validate_goose_metric3d_depth.py` |
| observation state | exact OCC fusion rays, poses, and sparse OCC | compressed observation NPZs | `validate_goose_observation_masks.py` |
| release assembly | all finalized relative-path products | v1.4.0 metadata and checksums | `build_goose_release.py` |

### Occupancy construction

Labels use the target LiDAR coordinate system (`x` forward, `y` left, `z` up)
and the half-open range `[0,50) x [-16,16) x [-4,4)` m. For a neighboring
semantic cloud, points are transformed with

```text
T_target_source = inverse(T_global_target) @ T_global_source.
```

The target plus at most five earlier and five later semantic clouds from the
same route are fused when their planar pose distance is no greater than 30 m.
Vehicle and human points are removed from non-target sources to limit dynamic
ghosting but retained in the target cloud. Raw GOOSE IDs are mapped to the
seven occupied classes before 0.25 m voxelization. Majority point count
selects the class within a voxel; ties use the lower stored ID. Sparse files
contain occupied IDs `1..7` only, in `[x,y,z,class]` order. This policy produces
145,982,332 occupied voxels over the release and is distinct from the dense
free/unknown interpretation applied later by an evaluator.

### Temporal camera and weak labels

Temporal histories are real causal camera frames sampled near
`t-0.2,...,t-2.0` seconds within the same bag. They are not OCC fusion sources
and are not constructed from `source_stamps_ns`. Camera timestamps are joined
to the pose timeline using the validated target camera/LiDAR clock anchor.
Histories without a pose within the allowed tolerance are excluded; target
images are never copied to fill a short history. The release contains 32,703
valid target-history relations and 31,644 unique history images. Temporal
infos cover 2,826 train and 485 validation targets; the common ten-history
experiment subset is further frozen to 2,726/469.

Official target 2D labels are mapped through the released 2D-to-OCC LUT. SAM3
propagates those semantics from the nearest eligible future target to history
images and writes class IDs `1..7` or `255`; confidence is stored separately
and zero confidence is invalid. Metric3D v2 ViT-L produces target and history
pseudo-depth independently of OCC GT. Depth is stored as uint16 PNG with
`depth_m = value / 256`. LiDAR comparisons reported by the dataset are offline
quality audits only and do not provide training targets or per-image scale.

### Observation-state release

Observation generation replays the exact semantic LiDAR sources used for OCC
construction. Ray traversal supplies known-free evidence and semantic
endpoints supply occupied evidence; occupied endpoints override free. Visible
occupied voxels require target-LiDAR support and an unobstructed voxel line of
sight. Occluded occupied voxels require target-camera occlusion and
non-target-source endpoint support. Voxels within 1.5 m of the target camera
are excluded from the V/O domains.

The complete v1.4.0 validation reports zero missing files and a valid mask
contract for all 3,367 targets. Across the release, the V-valid domain contains
436,526,372 voxels and the O-valid domain contains 289,585,746 voxels. These
counts and definitions come from
`observation/observation_validation.json` and
`observation/observation_protocol.json`; VisibilityOcc does not recompute or
reinterpret them.

## Frozen training/evaluation boundary

VisibilityOcc training reads RGB, target official 2D semantics, history SAM3
semantics/confidence, Metric3D target/history depth, intrinsics, and poses.
It does not read OCC labels or observation masks in the training pipeline.
OCC labels and the v1.4.0 observation files are loaded by the validation
pipeline only. `source_stamps_ns` and `source_distances_m` document OCC-label
fusion provenance and are never camera-history indices.

The existing sparse OCC loader initializes unwritten voxels as class `free=0`;
therefore standard baseline metrics retain the documented unknown-as-free
limitation. V/O metrics instead use the released protocol:

```text
V-valid = visible_known_free_mask | visible_occupied_mask
O-valid = occluded_known_free_mask | occluded_observed_mask
```

`fov_mask.npy` is a geometric camera-frustum mask and is not an occlusion
label.
